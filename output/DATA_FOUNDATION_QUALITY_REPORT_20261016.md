**茅台实证**：

| 库 | 口径 | 覆盖 |

| `bars_tdx.db` | **unadj（原始价）** | **2001-08-27 ~ 2026-10-16**（3,534 行，全历史） |

抽查：`600519.SH 2010-06-01`、`2015-06-01` 在 **bars.db 里查不到**，在 bars_tdx.db 里有原始价（132.63 / 271.46）。

### 3.2 根因（代码级，已定位到行）

`C:\Users\Administrator\ DSH 量化交易系统\deepseek-harness-quant\data\import_tdx.py`

```python
# L413-414：只取「正」因子
"SELECT code, date, qfq_factor FROM adj_factor "
"WHERE qfq_factor IS NOT NULL AND qfq_factor > 0", con)
# L426：内连接 → 因子非正的 (code,date) 直接消失，且不报错
m = bar.merge(af, on=["code", "date"], how="inner")
```

而 `adj_factor.qfq_factor` 在历史段**大量为非正值**：

- 全库 `qfq_factor <= 0`：**738,755 / 18,481,691 = 4.0%**
- 分年占比：1995 年 31.7%、1998 年 17.6%、2005 年 **27.4%**、2010 年 3.3%、2014 年 2.7%、2017 年 0.17%、**2022 年起为 0**
- 茅台：因子 2001-08-27 起为负（-8.79），**2016-07-04 首次转正（+0.0079）**——正好等于 bars.db 中茅台的最早日期

**因果链闭合**：早期因子为负 → `qfq_factor > 0` 过滤 + inner join → 该 (code,date) 不生成 qfq 行 → `bars.db` 只由 qfq 行构建（`switch_to_tdx_bars.py` L99 `WHERE adjust='qfq'`）→ **生产主库永久缺失这段历史**，且全程无任何报错。

### 3.3 附带发现：因子列语义与注释不符

`import_tdx.py` L400 注释写"前复权价 = 未复权价 × qfq_factor（通达信因子已以最新日为 1.0）"，但实测：

- 茅台因子从 **-8.79**（2001）单调升到 **+0.98**（2026），**不是**以最新日为 1.0 的正乘数；
- 负值时 `close × factor` 会得到负价格——这也正是当初加 `> 0` 过滤的原因。

→ **该列的口径存疑，重建前必须先确认语义**（很可能是某种累计收益率/差值型字段，而非复权因子）。这一步不确认，任何"补回历史"的做法都可能引入错误价格。

### 3.4 影响

- HANDOFF 的"日期范围 2000-04-03 ~ 2026-10-16（27 年）"在**总量**上成立，在**个股深度**上不成立：**最核心的长历史蓝筹在 2017 年前缺失**。
- 任何 2017 年前的回测/因子，其股票池是"**幸存者 + 短历史股**"样本：茅台、五粮液、格力、汾酒、万华、兖矿等不在样本内 → 价值/质量/动量类因子的早期截面被系统性扭曲。
- 该缺陷会让所有"用全历史"的结论（含 P0-2 之外的历史回测）低估/偏置。

### 3.5 修复建议（**需你确认后再动手**，因涉及 5 GB 主库重建）

1. **先定语义**：确认 `adj_factor.qfq_factor` 的真实口径（读通达信因子文件说明 / 用 2-3 只已知除权股手工验算）。
2. **重建 qfq**：对每个 (code,date) 生成 qfq 行——原料已具备（`bars_tdx.db` 有全历史 unadj 3,534 行/茅台 级覆盖；原始日 K 文件仍在 `D:\BaiduNetdiskDownload\全A日K`）。
3. **加护栏**（比修复本身更重要）：
   - 把 `how="inner"` 改为左连接 + **显式统计并报出**未匹配行数，绝不静默丢行；
   - 数据切换脚本落地后跑一次"**行数对账**"（源 vs 目标差值必须为 0 或已解释）；
   - 把本报告 §3.1 的逐年缺失表纳入回归检查。
4. **验收**：重建后 `bars.db` 行数应 ≈ 16.37M（或对差值有书面解释），且茅台最早日期应为 2001-08-27。

### 4.2 根因（代码级）

`C:\Users\Administrator\ DSH 量化交易系统\deepseek-harness-quant\data\tdx_daily_update.py` → `write_bars()`（L111-137）：

```python
out["adjust"] = "unadj"
out["source"] = source
out["is_st"] = 0                      # ← L127：增量行 is_st 恒 0
cols = [r[1] for r in con.execute(f"PRAGMA table_info({TABLE})")]

    if c not in out.columns:
        out[c] = None                 # ← turn 不在 API 字段里 → 全部填 None
```

即：增量路径**不计算 `turn`**（API 的 `FIELDS` 里没有换手率），也**不判断 ST**。

### 4.3 影响

- **`turn` 类因子在增量段整体失效**（`turn_low` 是本项目主仓位口径，见 AGENTS.md"主仓位 turn_low 分散"）。

- 影响随时间累积：每过一天，最近 N 天的 ST 过滤与换手因子就多一天空洞。

### 4.4 修复建议

1. 增量写入后用**流通股本**补算 `turn = volume / 流通股 × 100`（流通股本可取自 `get_gb_info` / `tdx_meta`），或改调通达信含换手率的字段；
2. `is_st` 改为查 `tdx_meta.stock_info_snapshot`（每日快照已在上报）或 `stock_info_tdx.IsSTGP` 回填，**不要写死 0**；
3. 在 `write_bars` 末尾加**字段完整性断言**：turn/is_st 缺失率 > 阈值即报错退出，避免无声劣化；
4. 补历史：把 2026-10-12 起的 27,860 行 turn/is_st 回填。

这与 `AGENTS.md` 铁律③「换手率（turn）2019 年前缺失 → 2019 前换手类结论一律作废」**直接冲突**。

**但不能据此解除铁律**，理由：
1. 铁律来自**旧数据源**（Tushare/baostock 段 turn 缺失）的实证，新源换了，前提确实变了；
2. 新源的换手率是**通达信算法**（通常 = 成交量 / 流通股本），其分母（历史流通股本、含限售/解禁时点）**尚未校验**；
3. 早期流通股本数据本身易错，若分母错，换手率会系统性偏差。

**建议的抽验方案**（1-2 小时可完成，需你点头）：
取 5-10 只已知股本变动事件的股票（如大比例送转/解禁），把 bars.db 的 `turn` 与"成交量/当时流通股本"手算值、以及 2019 年后与 `valuation.turn` 的交叉一致性做对比；若 2019 前后一致且与公开值吻合，再考虑**修订**铁律③（而不是直接删除）。

## 9. 单位与复权口径（澄清一个易误判点）

`amount/(volume×close)` 在 qfq 表里逐年从 **7.72（2000）**降到 **1.02（2026）**，**这不是单位错误**：

- `close` 是**前复权**价，`volume`/`amount` 是**未复权**原值（正确做法：成交量/额从不复权）；
- 因此该比值实际是"**复权倍数指示**"（≈1 表示接近基准日）；
- 真实单位校验应使用未复权行：`601318.SH 2010-06-01` VWAP = amount/volume = **45.779**，落在当日 `[44.8, 46.4]` 区间内 ✅；`600519.SH 2026-10-16` VWAP = 1,317.70 ∈ `[1301.68, 1329.88]` ✅ → **volume 单位为股、amount 单位为元，口径自洽**。

**交叉验证**（qfq 基准日应等于 unadj）：

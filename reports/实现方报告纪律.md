# 实现方报告纪律（对端 AI 必须遵守）

> 定版：2026-10-18　|　适用：所有轮次（R0 起）的所有报告
> 上位文件：`AGENTS.md` §团队原则（T1–T5）+ §决策纪律（D1–D7）
> **本文件是 PM 与实现方之间的契约。每份任务书都默认引用本文件，不重复粘贴全文。**

---

## 零、前提：出错不会被指责

用户（决策者）已明确：**不会因为出错而指责，要求的是如实汇报，便于及时调整。**

因此：

| # | 含义 |
|---|---|
| **P1** | 你**没有动机**隐瞒失败、美化数字、或把"没跑通"包装成"部分成功" |
| **P2** | 报告"这条路线失败、有效 0 个"是**合格交付**，不是失误 |
| **P3** | 报告"我的实现有 bug、已修复、影响如下"是**加分项**，不是丢脸 |
| **P4** | 反过来，**隐瞒 / 美化 / 含糊**才是真正的失误 |

## 一、报告纪律（R1–R10，硬性）

| # | 规则 |
|---|---|
| **R1** | **失败原样报**：跑不通、跑不出、结果全 NaN，直接说，附错误原文。禁止用"部分成功""基本完成"包装 |
| **R2** | **数字不许美化**：保留原始精度（如 `−0.0159` 而非"约 −1.6%"）；必须舍入时标注"已舍入到 X 位" |
| **R3** | **无数据写"无"**：不许猜、不许留空、不许用相邻值顶替 |
| **R4** | **实现 bug 必须主动披露**：包括在过程中发现并已修复的（写明：哪里错、错多久、影响了哪些已报数字） |
| **R5** | **禁止为过门禁而调参**：不许改阈值 / 缩样本 / 换窗口 / 删因子。任务书列了禁止项，逐条遵守 |
| **R6** | **与 PM 预期不符时必须主动对比**：任务书含"PM 预期"表的，逐条对照并解释差异；不确定就写"无法解释" |
| **R7** | **近似与替代必须标注**：如"现金收益用年化 2% 近似（511990 无分红记录）"必须写进报告与 JSON |
| **R8** | **样本不足必须标注**：如 T4 杠杆数据仅 2016+，不得与 2008/2015 并列比较而不注明 |
| **R9** | **交付必须自证 hash**：报出本地 `HEAD` 与 `git ls-remote origin master` 两个完整 hash，二者必须相同 |
| **R10** | **被 PM 打回时不许原样重提**：必须写明"上一版哪里有问题 + 这一版改了什么 + 如何验证" |
| **R11** | **每个数字必须带出处标注**：格式 `-1.59% [src: 文件名.json#json.路径]`。PM 用 `scripts/pm/audit_citations.py` 自动核对——标注写错或路径不存在 = 报告作废 |
| **R12** | **跑之前先预申报预期**：在 `reports/<轮次>_预期申报.md` 写下你认为会得到什么（含数值区间）。跑完必须对照申报逐条说明「符合 / 不符合 + 为什么」，禁止事后合理化 |

## 一之二、机械保障：三道防造假闸门（叮嘱没用，机制才有用）

| 闸门 | 机制 | 为什么无法绕过 |
|---|---|---|
| **闸 1 溯源** | 每个数字带 `[src: file#path]`，`audit_citations.py` 自动回 JSON 取值比对 | 编一个好看的数，路径不存在或数值不符，直接 FAIL |
| **闸 2 交付** | 只认 `git ls-remote` 能看到的 hash + 文件；`check_delivery.py` 查远端树 | 说已完成但没推，台账显示 MISSING |
| **闸 3 预申报** | 跑之前先写预期，跑完必须对照 | 想事后解释成符合预期，申报文件的时间戳会揭穿 |

### 溯源标注示例

```markdown
| 项 | 值 |
|---|---|
| 策略夏普 | 0.334 [src: b1_single_asset.json#index."2016+".strategy.sharpe] |
| 买入持有夏普 | 0.152 [src: b1_single_asset.json#index."2016+".buy_hold.sharpe] |
| 最大回撤 | -35.78% [src: b1_single_asset.json#index."2016+".strategy.max_drawdown] |
```

提交前自检（显示"全部数字可溯源"才算完）：

```bash
python scripts\pm\audit_citations.py reports\<你的报告>.md
```

## 二、报告格式（与 PM 看板 §零之二 F6 一致）

```markdown
【<轮次>】执行报告

| # | 项 | 结果 |
|---|---|---|
| 1 | 轮次 | R3-0 |
| 2 | 本地 HEAD | <40位hash> |
| 3 | 远端 HEAD | <40位hash> |
| 4 | 两 hash 一致 | 是 / 否 |
| 5 | 交付文件 | <逐条：路径 + 字节数 + 存在/缺失> |
| 6 | 关键数字 | <按任务书要求，逐个字段> |
| 7 | 与 PM 预期差异 | <逐条对照，无差异写"无"> |
| 8 | 近似/替代 | <逐条，无则写"无"> |
| 9 | 样本不足标注 | <逐条，无则写"无"> |
| 10 | 实现 bug 披露 | <有则详述，无则写"无"> |
| 11 | 失败/异常 | <原样附错误原文，无则写"无"> |

结论：通过 / 不通过 / 部分完成（三选一，并说明理由）
```

## 三、禁止的表述（PM 会直接打回）

| # | 禁止说法 | 应该怎么说 |
|---|---|---|
| 1 | "已完成，工作区干净" | 附本地/远端两个 hash，证明已 push |
| 2 | "结果基本符合预期" | 给出数字，并列出与预期的差异 |
| 3 | "因子表现尚可" | 报出净超额 / 夏普 / 回撤 / Calmar 四个数 |
| 4 | "部分数据缺失，已处理" | 说明缺哪些、缺多少、如何处理、对结论的影响 |
| 5 | "已优化参数" | **除非任务书明确要求**，否则这就是违规（R5） |
| 6 | "夏普 1.1，效果显著" | 同时报回撤、Calmar、触发频率、牛市代价 |

## 四、PM 侧的对等义务

| # | PM 必须做到 |
|---|---|
| 1 | 判读基于**产物**（JSON/文件/hash），不基于叙述 |
| 2 | 打回时必须写明**具体差在哪一条门禁**，不许只说"重做" |
| 3 | PM 自己的错误也进 `AGENTS.md` 错误台账（E1–E5 已留档） |
| 4 | 门禁设错时**PM 先认错再改**，不许让实现方背锅 |

## 一、本轮的定位（必须先读）

**R4 不是"证明 T5 有效"，而是"用样本外数据累积新观测"。**

| 是 | 不是 |
|---|---|
| ✅ 建立每日信号记录与前向验证卡 | ❌ 不做参数优化 |
| ✅ 冻结全部参数后开始观察 | ❌ 不做历史回测重判 |
| ✅ 12 个月后按预注册判据判定 | ❌ 不在观察期内下"有效/无效"结论 |

**原因**：R3-0/R3-1/R3-2 已经把同一份 2005-2026 历史用了三遍。再用第四次就是数据窥探。
**唯一能产生干净样本的方法：等未来发生。**

## 二、5 把锁（**全部写死，任何一把被破即本轮作废**）

### 锁 1：参数冻结

以下参数**一个字不许改**，直到 12 个月观察期结束：

| 项 | 冻结值 |
|---|---|
| 信号定义 | `lift_t = corr60_t − median250_t > 0.05` |
| `corr60_t` | 过去 60 个交易日，**4 个权益指数**日收益的两两相关平均值（相关系数对数 = C(4,2) = 6 对） |
| `median250_t` | `corr60` 在过去 **250 个交易日**的**中位数**（trailing，有效值 <100 时视为无信号） |
| 阈值 | **+0.05**（不是 0.03，不是 0.07） |
| 档位 | **D0**：信号=1 → 仓位 **0%**；信号=0 → 仓位 **100%** |
| 执行 | **t 日收盘算信号 → t+1 日开盘调仓** |
| 成本 | 单边 **0.036%**（`config/costs_etf.yaml`） |
| 现金收益 | **0%**（与 R3-2 一致，保证可比） |
| 标的 | `000300.SH`（沪深300指数，通达信直取） |
| **4 个指数代码** | **必须先从 `scripts/r3_2_t5_robustness.py` 中确认 R3-2 实际使用的 4 个代码，原样冻结，并在报告中列出** |

> ⚠️ 最后一行是硬要求：若 R3-2 用的不是 000300/000905/000852/399006，**以 R3-2 实际使用的为准**，不许换。

### 锁 2：判据预注册

**必须在观察开始前**提交 `reports/R4_预注册判据.md`，写入第四节的全部判据。
- git 提交时间戳必须早于第一天的观测日志
- 提交后**不许修改**（修改即视为锁 2 被破）

### 锁 3：最小事件数

| 规则 |
|---|
| 必须观察到 **≥2 个完整触发段**（信号从 0→1 到 1→0 算一个完整段）才能下结论 |
| 12 个月到期但不足 2 段 → **延长观察**，不许用"没触发"推断有效或无效 |
| 完全无触发 → 如实报告"条件未出现，无法验证"，这本身是有效结论 |

### 锁 4：改动即清零

| 规则 |
|---|
| 观察期内若修改任何冻结参数 → **观测计数重置为 0**，重新开始 12 个月 |
| 若修改代码逻辑（非 bug 修复）→ 同上 |
| **bug 修复例外**：必须单独提交，写明"修了什么 bug、影响哪些已记录数据、如何补正" |

### 锁 5：损失上限

| 规则 |
|---|
| 若观察期策略净值相对基准的累计超额 **< −5%**，**立即停止观察并复盘** |
| 停止后必须写复盘报告，说明是 whipsaw、还是信号失效 |

## 三、观察协议（每天做什么）

### 3.1 每日信号记录

脚本 `scripts/r4_t5_paper_trading.py`，每次运行：

1. 取最新交易日数据（通达信）
2. 计算 `corr60`、`median250`、`lift`
3. 判定 `signal`（0/1）
4. 按 t+1 开盘执行，更新模拟净值
5. **追加**到 `reports/r4_t5_daily_log.csv`

### 3.2 日志字段（必须全部有）

| 字段 | 说明 |
|---|---|
| `date` | 交易日 |
| `close` | 沪深300 收盘 |
| `corr60` | 60 日平均两两相关 |
| `median250` | 250 日中位相关 |
| `lift` | corr60 − median250 |
| `signal` | 0 / 1 |
| `position` | 当日收盘后持仓（0.0 / 1.0） |
| `nav_strategy` | 策略净值（起点 1.0） |
| `nav_benchmark` | 基准净值（起点 1.0） |
| `trades` | 当日是否调仓（0/1） |
| `cost` | 当日扣除成本 |
| `note` | 异常说明（如数据缺失） |

### 3.3 事件验证卡

每个触发段开始时，立即创建 `reports/r4_events/<t0日期>.md`，写入：

| 字段 | 何时填 |
|---|---|
| `t0` | 触发日 |
| `corr60 / median250 / lift` | 触发日当天数值 |
| `市场当时位置` | 距 250 日高点回撤 |
| `t+20 / t+60 / t+120 市场收益` | **事后回填** |
| `段内市场最大回撤` | **事后回填** |
| `本段判定（命中/未命中）` | 事后回填（判据：t+60 市场收益 < 0 → 命中，与 R3-0 口径一致） |

### 3.4 运行频率

| 频率 | 动作 |
|---|---|
| **每个交易日**（或至少每周）| 跑脚本更新日志，`git commit` 追加 |
| **每月末** | 写一份 `reports/r4_monthly/YYYY-MM.md`：当月信号状态、净值、有无触发 |
| **每次触发开始时** | 建事件验证卡，commit 后告知 PM |
| **观察期结束** | 写 `reports/R4_观察期总结.md`，按预注册判据判定 |

## 四、预注册判据（12 个月后用，现在就定死）

### 4.1 主判据（事件命中率）

| 项 | 标准 |
|---|---|
| 样本量门槛 | 完整触发段 **≥2** |
| **命中定义** | 触发后 **60 个交易日**市场收益 **< 0** |
| **通过标准** | 命中率 **≥ 50%**（2 段中至少 1 中，3 段中至少 2 中，以此类推） |

### 4.2 辅判据（净值表现，仅作参考不作判定）

| 项 | 记录但不作判定依据 |
|---|---|
| 观察期策略净值 vs 基准净值 | 报告 |
| 观察期夏普（若天数 ≥120） | 报告 |
| 换手次数与累计成本 | 报告 |

> **为什么净值只作参考**：12 个月的样本太短，净值噪声远大于信号质量。用净值定生死会误判。

### 4.3 否决条件（任一触发即判失败）

| # | 条件 |
|---|---|
| V1 | 触发后 60 日市场收益为正的次数 > 命中次数（**多数判错**） |
| V2 | 观察期累计超额 < −5%（锁 5） |
| V3 | 参数被修改（锁 4） |
| V4 | 出现数据缺失但未标注（R1/R3 违反） |

### 4.4 观察期不足的处理

| 情况 | 处理 |
|---|---|
| 12 个月但 <2 段 | **延长 6 个月**，最多延长到 24 个月 |
| 24 个月仍 <2 段 | 判定"**条件过于罕见，无法在可接受时间内验证**"，写入证伪日志，进入长期探针 |
| 观察期内触发 ≥5 段 | 可**提前**按主判据判定（样本已足） |

## 八、PM 预判（写下来，12 个月后对照）

| # | 预测 |
|---|---|
| P1 | 12 个月内触发段数 **≤3**（R3-2 显示 3.44 次/年，但近两年偏少） |
| P2 | 可能出现 **1-2 次 whipsaw**（触发后市场反而上涨），因为 2025 年就出现过 2 次（2025-04-07、2025-05-20） |
| P3 | 若出现 ≥2 次 whipsaw，命中率会低于 50%，判失败 |
| P4 | 观察期净值表现大概率**跑输基准**（因为 2024-2026 是震荡上行，空仓吃亏） |
| P5 | 但即使跑输净值，若事件命中率达标，仍判"信号有效但短期成本高" |

> **P4 很重要**：我预期它在未来 12 个月可能亏钱。**如果因为亏钱就改参数，那就是过拟合。**
